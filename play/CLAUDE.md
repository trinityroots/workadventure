# CLAUDE.md - play/

Svelte/Phaser frontend, pusher server, and Room API server.

## Areas

- `src/front/`: browser application, Svelte UI, Phaser, media, and WebRTC.
- `src/pusher/`: WebSocket and HTTP server-facing logic.
- `src/room-api/`: Room API implementation.
- `src/i18n/`: source translations and generated types.
- `tests/`: Vitest tests; additional tests are colocated under `src/`.

## Common commands

```bash
cd play

npm run typecheck
npm run svelte-check
npm run lint
npm run pretty-check
npm test
npm run build
```

Prefer checks over mutating commands during validation. Use `npm run lint-fix` and `npm run pretty` only when fixing files.

Run a focused unit test once:

```bash
cd play
npm test -- --run tests/front/Utils/TokenBucket.test.ts
```

## Generated prerequisites

After changing protobufs, generate messages from `messages/`. After changing translation keys, run:

```bash
cd play
npm run typesafe-i18n
npm run i18n:check
```

A new key must be added to **every** locale under `src/i18n/<locale>/`, or `i18n:check` fails.

Do not edit generated `src/i18n/i18n-*.ts` files directly.

## Frontend conventions

- The session JWT never travels in a URL: browser calls send `Authorization: Bearer`,
  pusher handlers (`/me`, `/logout`, `/profile-callback`) accept only that header and
  answer 401 without it, and post-login handoffs write `localStorage.authToken` through
  `redirectToRoom.html`/`redirectToMatrix.html` instead of appending `?token=`.
- New and migrated Svelte components use Svelte 5 runes (`$props`, `$state`, `$derived`, `$effect`).
- Panels the action bar opens (agenda, tasks, chat, users) are tabs of the chat sidebar:
  `navChat.switchToCustomComponent(...)` plus `chatVisibilityStore.set(true)` — never a second
  absolutely-positioned drawer, which would duplicate the close control and sit open beside the users list.
  The profile menu's Inventory entry (`Components/Inventory/sidebar.ts`) opens a
  `GameWindow/FloatingWindow` instead (`inventoryOpenStore`; `openInventory()` also closes
  the NPC panels so two windows never stack).
- Item art and stats: `Components/Inventory/items.ts` mirrors the game catalog (ids,
  slots, `attack`, `rollMax`, `potion`) and its `statsText()` feeds the tooltips; the icons
  are `public/static/images/items/<id>.png`, one per catalog item, full-colour pixel art
  from Allexio/Pixel-RPG-icons (CC0-1.0), regenerated to 64×64 on a transparent canvas
  (content box 56px, NEAREST) and served through `iconUrl()` with `?v=8` so a pack swap
  busts the browser cache. The pack has no glove sprite, so `work_gloves`/`item_gloves`
  use `items/Fabric.png` as the closest match.
- The chat drawer's search field is always visible in its header; Cmd/Ctrl+K opens the user list
  and focuses it (`Components/searchShortcut.ts` decides the keystroke, `chatSearchFocusRequest`
  asks the header to take focus). The map script no longer registers its own search button.
- Calendar meeting-room events keep the room URL in the Google Calendar event *location* with a bare
  area name in the hash (`…/~/trinityroots/office.wam#Lounge`). `CalendarJoinButton.goThere` walks the
  player to that area in place; `#moveTo=<area>` is the in-app link form.
- The calendar connect flow is `CORE_URL/auth/google?return=<play origin>`; core redirects back with
  `?calendar=connected`, which `consumeCalendarConnectedParam()` (CalendarLoader) strips before the
  first refresh. The panel's Connect button shows whenever `isActivatedStore` is false.
- Mic auto-mute: `startMicAutoMute()` (MainLayout onMount) mutes an idle microphone when the window
  loses focus or the tab hides (`focusStore` + `visibilityStore`, same machinery as PrivacyShutdown);
  `isInActiveConversationStore` gates it so a running conversation keeps its mic.
- NPCs come from the game service (`Services/npcList.ts`, `GET /api/game/npc/list`) and spawn
  as native entities with the player-style `UsernameDisplay` badge whose availability dot is
  replaced by a 13px role icon (`Phaser/Components/npcRoleIcons.ts` — themed-color PNGs at
  `public/resources/icons/npc-<name>.png`, rendered as a plain `<img>`; each icon carries its
  own palette, e.g. gold scroll, green leaf, teal flask). The glyphs are game-icons.net
  artwork (github.com/game-icons/icons, CC BY 3.0) tinted per icon onto full transparency
  (no chip or border — `?v=8`, generated by `tmp/wa-npc-reloc/compose_icons_flat.py`).
  NPC sprite sheets carry sit rows 4-7 (rebuilt by `tmp/wa-npc-reloc/fix_sit.py`), but the
  sit art was rejected as broken: no NPC uses it — every NPC stands on the middle
  frame of its direction row, never mid-stride (`pose: "sit"` from the game service still
  selects sit rows if an admin sets it). Sheets whose art changed are served with `?v=2`
  because play's static files use `max-age=86400` — and `MonsterManager.loadTexture` reserves a unique
  key per URL load (a shared key once made every NPC render the first sprite). Badge icons
  size with `calc(px * var(--username-dom-scale, 1))` so they track zoom like the status dot. Clicking one walks the player
  to an adjacent tile (`GameScene.onNpcClicked`) and opens `NpcChat/NpcChatPanel.svelte` on
  arrival; **X** opens the nearest NPC within 120px (same focus/input guards as calendar's L). Opening a chat seeds the NPC's `greeting` (from `GET /api/game/npc/list`) as the
  first NPC message, so every conversation starts with what you can ask that NPC about.
  **Every fixed overlay must carry `pointer-events-auto`** (RpgDialog, FloatingWindow, GamePanel, TradePanel): the MainLayout root is `pointer-events-none`, and without the
  class every click falls through to the game canvas — the panel renders but nothing responds, which reads as a freeze.
  The chat panel is a centered modal built on `NpcChat/RpgDialog.svelte` (pixel-JRPG theme:
  navy frame, pop-yellow accents, dimmed backdrop; the player's own lines are parchment
  bubbles) — not a drawer, not a chat-sidebar tab; i18n keys live under `npcChat`. The modal
  is `w-[640px]` fixed at `60dvh` with a `360px` floor, focuses its input on open (an
  `$effect` keyed on the open NPC plus a 150ms refocus — the panel is inside an `{#if}`, so
  `onMount` fires at app start, and Phaser can steal focus while it mounts), streams
  deltas live, and renders assistant messages as sanitized markdown (`NpcChat/markdown.ts` —
  marked + DOMPurify; `.npc-md` styles in the panel). Shop,
  leaderboard and inventory use `GameWindow/FloatingWindow` instead (centered card over a
  dimmed backdrop, same frame family as the chat modal). Esc closes every NPC panel —
  RpgDialog and FloatingWindow each bind their own `svelte:window` keydown handler.
- Shop NPCs open `NpcChat/ShopPanel.svelte` as a wide `GameWindow/FloatingWindow` laid out
  like a craft station (`Services/shop.ts` store): the window is fixed at `h-[52vh]`
  (FloatingWindow `heightClass`, deliberately shorter than the chat modal's `60dvh`) and the
  left slot grid scrolls under `max-h-[38vh]` with a
  native scrollbar once it outgrows that. Left parchment slot grid of pixel icons
  (`Inventory/items.ts` `iconUrl`), a static preview box in the middle that fills with the
  selected item's art, the per-shop station glyph + the primary action (BUY/SELL/REROLL/USE, green CREATE-style button), right DESCRIPTION
  parchment with stats as `◆` lines — Bram/Nell catalogs, Rilla sell-back, Moss reroll
  shows `◆ +roll` / `◆ max +rollMax`, Sable market stock with a closing countdown (its
  entity only exists while `/api/game/market/status` says open, re-checked every 30s).
  Only Rilla and Moss list the player's own items (sell / reroll); Bram, Nell and Sable are
  pure catalogs. Potions carry `potion: true` in `Inventory/items.ts` and are consumed by
  clicking them in the Inventory bag (`usePotion` → `/api/game/potion/use`, then a refresh).
- Leaderboard boards also arrive as NPC entities with `kind: "board"` (`Services/leaderboard.ts`,
  `GET /api/game/boards`); the sprite is `resources/npcs/board.png?v=5` — a hand-drawn medieval
  freestanding notice board built with pixel-art depth cues: a perspective top face (trapezoid),
  a lit inner lip on the right rail for thickness, a ground cast shadow, ambient occlusion under
  the panel, the cross brace drawn behind the posts, and drop shadows under the five pinned notes
  (generated by `tmp/wa-npc-reloc/make_board_v2.py`, no external art license) loaded
  as a single 96×80 frame (`Monster.ts` overrides the spritesheet frame size for `board.png`,
  origin `(0.5, 1)` so the feet sit on the tile, `setScale(0.75)` so it reads as map furniture
  at 72×60 on screen, spawn uses frame 0); no name badge, but the click target stays (a 72×60
  hit area covering the panel and the legs).
  Click or X opens `NpcChat/LeaderboardPanel.svelte` (a `FloatingWindow` at `w-[1024px]`
  `h-[60vh]` so the body scrolls inside, star `titleIcon` in the header, header text = the
  board's admin title, currently "Roots Board"): the board never reveals its metric
  or scores — the header shows a per-metric riddle and every score renders `??`, only the
  ranking is real. The panel is tabbed: `BoardInfo.tabs` comes from the game service sorted by
  admin `sortOrder`, a `leaderboard` tab shows the riddle + ranking, an `html` tab renders the
  admin-authored content in a sandboxed `<iframe srcdoc>` (full HTML + `<style>` allowed;
  `sandbox="allow-popups"` keeps scripts off), and the window title follows the active tab.
  Opens only when the player is in range (X prefers a nearer NPC).
- `Services/presenceHeartbeat.ts` (started in MainLayout) posts `/api/session/heartbeat` every
  60s and `/api/session/leave` on `pagehide`; core turns that into the presence audit.
- The game panel (`Components/GamePanel/`) is a standalone quest tracker pinned to the right
  edge at `top-24` (the top-16 slot collides with the Tools/Share/user-menu header row),
  rendered by MainLayout directly and always visible — it has no close control, so there is
  no open/closed store and no action-bar entry. Collapsed it shows only the header bar
  (title + expand control); the header is one full-width button, so a click anywhere on it
  toggles, and the cards are separated by dividers rather than a border box per row.
  Expanded it lists every quest as compact rows
  (200px wide, 13px titles, hairline progress bars, `p-0.5`/`px-1.5 py-0.5`; the reward
  line is `mb-0 leading-none` and the progress bar sits flush (`mt-0`) under it, other
  sub-rows use `mt-px`; **J** toggles (Q is WorkAdventure's AZERTY move-left key);
  a 45s poll auto-expands
  when a new assignmentId appears)
  (`Services/quests.ts`, claim). The shell is translucent like the top bar
  (`bg-contrast/80 backdrop-blur`); the header carries the borderless npc-role `item_bag`
  glyph (kept distinct from Rowan's `scroll`) plus a mono uppercase pop-yellow title, and each row's type marker is pixel art
  (kill `item_sword`, visit `npc-map`, talk `npc-quill`, collect `item_bag`, timesheet
  `npc-scroll`) rather than an emoji, with purple→gold
  gradient progress bars, gold CLAIM
  buttons and an emerald tint on ready quests; Esc on an expanded tracker collapses it.
  Quest view only — the achievements UI was removed with the tab nav. Leaderboards are not
  in it — boards are walk-to map objects only.
- Game feel (`Services/gameSfx.ts`): synthesized WebAudio chiptune effects, no audio files —
  `playSfx(name)` for NPC click pop, chat greeting ding, claim fanfare, coin for buy/sell,
  ding for reroll/use, a hand-wave blip and a thud on monster hits. There is no global click
  tick and no open/close blip — panel opens and closes are silent. Combat VFX live in `Phaser/Entity/Monster.ts`
  (floating damage number, white flash, sprite shake, scale-out on remove); shop actions
  burst the slot (`slot-burst`) and pop the gold chip (`gold-pop`) in `ShopPanel.svelte`.
- Trade (`Components/Trade/TradePanel.svelte`, `Services/trade.ts`) is a right-side drawer fed by
  a 5s poll (`startTradePolling` in MainLayout). Entry point is the user-list action menu, which
  invites by Matrix handle; the game service resolves the handle back to a player email. Offers
  are item stacks + gold, both sides confirm, and the swap runs atomically in the game service.
- Match the translation import style and UI patterns of neighboring components.
- Event listeners and subscriptions must have explicit cleanup. ESLint checks listener removal and ignored subscriptions.
- For Phaser or media behavior, test actual runtime state rather than relying only on rendered DOM state.
